## 只是專案裡的一個任務

在專案檔把任務打勾、更新 L1／L2 和工作索引那一行，提交 git：`done: <任務>`。到此結束。

## 整個專案結束

1. **留下值得長期記住的部分。** 讀完整的專案檔，提議哪些內容轉進 `memory/knowledge/`（標明來源是這個專案）：
   - 最終結果和關鍵數字
   - 重要決策和理由
   - 踩到的坑、下次要注意的事
   - 過程中學到的公司知識（流程、誰負責什麼）
   主管偏好不在這一步處理，已經在 `/debrief` 時學過了。

2. **決定怎麼移除。** 使用者沒指定時，問他選哪一種：
   - **封存**：專案檔移到 `archive/`。之後不會出現在搜尋結果、不佔上下文，但問到過去的專案時還能找到。
   - **刪除**：用 `git rm` 刪掉專案檔。工作目錄裡完全不留，只能從 git 歷史找回。

3. **清理引用。**
   - 從 `memory/work/index.md` 移除該行。
   - `memory/knowledge/` 裡「相關專案」指向它的條目：封存時改成 `archive/<檔名>`；刪除時改成「（已結案：<專案名> <日期>）」。
   - 事件檔（`memory/episodes/`）保留不動，它們記錄的是主管的反應，跟專案是否結束無關。
   - `reports/briefs/` 裡這個專案的舊建議，選「刪除」時一併 `git rm`。

4. 先列出完整提案：哪些內容轉進知識、移除方式、會動到哪些檔。執行 `mv`／`git rm` 時會跳出確認。

5. 提交 git：`done: <專案> (<封存或刪除>)`。最後告訴使用者怎麼找回：封存的在 `archive/`；刪除的用 `git log --all -- memory/work/<檔名>` 找到刪除前的版本。
